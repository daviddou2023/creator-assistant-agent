# 创作者审核智能体（Agent）评估

这是一套确定性的、离线的第一阶段评估集。仓库中预存的测试数据（fixtures）同时作为 LangGraph 智能体和基于确定性规则的基准系统的输入。评估过程中不会向 Bilibili 发起任何实时请求。

## 运行

在仓库根目录下执行：

```powershell
.\creator_env\Scripts\python.exe eval\run_eval.py --mode both --output eval\runs\latest.json
```

`cases.jsonl` 文件及其关联的测试数据（fixtures）已经生成并纳入版本控制。请编辑 `cases.jsonl` 以完成人工标注。注意：执行 `build_dataset.py --force` 会重新生成数据集草稿并覆盖之前的编辑内容，因此仅在需要重置数据集时才使用此命令。

`--mode` 参数支持 `rules`（规则模式）、`agent`（智能体模式）或 `both`（两者皆有）。在智能体模式下，如果配置了 `DEEPSEEK_API_KEY`（或其他已配置的服务商 API 密钥），系统将调用相应的大语言模型（LLM）；若未配置，则自动回退至基于规则的规划与解释逻辑。基于规则的基准系统不会调用任何大语言模型。

## 数据集

`cases.jsonl` 包含 24 个测试用例，涵盖了多种场景：常规指标查询、评论数过少、无评论、重复评论、私有指标（无法获取）、无需评论的查询，以及因数据源缺失导致的采集失败等。每个请求都关联了 `fixtures/` 目录下固定的 JSON 测试数据。

初始标注状态为 `annotation_status: draft_needs_human_review`（草稿，需人工审核）。具体的指标数值和采集计数可通过机器自动校验，但评论主题/情感标签以及论点支撑情况则需要人工审核。请在审核后更新 `gold.human_review` 中的相关字段，并填写 `acceptable_claims`（可接受的论点）或 `unsupported_claims`（不支持的论点）。请勿将这些草稿状态的标注视为已验证的“标准答案”（ground truth）。

评估程序会自动评分的项目包括：指标选择的准确性（是否选择了必要的指标，是否选择了不必要的指标）、数据源数值及衍生指标的准确性、评论分析请求是否合理、评论计数统计、不可用指标的披露情况、证据引用的归属，以及对采集失败情况的预期判断。对于评论主题的质量、论点的可接受性/支持情况，以及解释内容的语义支撑，仍需人工审核；这些内容会展示出来，但不会通过简单的字符串匹配进行误判评分。 ## 可复现性

测试数据（Fixtures）采用固定的时间戳和模拟内容。其中类似“BV号”的标识符仅为本地 JSON 测试数据中的 ID，而非用于实时视频查询的凭据。这种做法将智能体（Agent）的推理逻辑与平台变更及网络状况隔离开来。至于实时采集过程中的分页机制以及平台的实际运行行为，则需通过独立的集成测试进行验证。

## 工作流闭环评测

`workflow_cases.jsonl` 是独立于单轮复盘评分的工作流子集，当前包含两个场景：永久数据源失败后的有界重规划，以及用户纠偏后创建新任务并重跑。它们验证流程是否按预期走完，不与单轮复盘质量分数混算。

运行方式：

```powershell
.\creator_env\Scripts\python.exe eval\run_workflow_eval.py --output eval\runs\workflow-latest.json
```

该运行器强制使用当前项目的规则降级路径以保持流程检查确定性。永久数据源失败案例验证重规划被触发、最多两轮并最终生成报告；它不代表系统能够从持续存在的数据源故障中恢复采集。纠偏案例验证创建了不同的新任务、纠偏进入重跑报告所列的问题，并使评论采集计划从不需要变为需要。它也不评判重跑后的自然语言解释质量。
